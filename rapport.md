# En kort lille beskrivelse af denne rejse fra start til slut

## En beundringsrigt valg af brug ved Typescript, Javascript, Hono og Mongodb

Det første jeg overhovedet valgte at gøre var at vælge noget JEG kunne bruge til mine egne personalige hjemmesider.
til det vil jeg ha brug af ikke kun Frontend til at skabe en beundringsværdig syn men også kunne lave en backend til at skabe en mere fleksible string og data til brug for frontend siden. fordi jeg har allerede arbejdet med Mongodb valgte jeg at fordybe mig dyber ned i havets backend og skabe en router og connection til min backend via brug af typescript og hono vedsiden af javascript og Mongodb værktøjer til det. 

## Hvorfor Mongodb? Hvad er dette noget NoSQL i forhold til det der SQL?

Så SQL er en Strukturet Database som har gemt data i en strukturet tabel med predefineret schemaer, primaert lavet for complex quieries.

NoSQL er en database som bruger fleksible data modeller så som dokumenter, key-value, graph og column vendelig og er idealt for stor skaleret 
, oftest ændrene application.

Mongodb passer ind til hvad jeg har behov for. Mongodb giver mig en rig mulighed for udvikling til routing i Visual studio code 
som giver en kraftful, dokumentorienteret NoSQL Database, den fylder de moderne applikationer behov med hensyn til skalerbarhed.

## Hvorfor Hono?

Hono er en simpel web application framework som er ret tæt på express men uden frontend, den køre på noget der heder CDN Edges som giver dig mulighed for at bygge store applicationer når den combinere med middlewhere
noget som Edge Application, Proxy of backend servers, full-stack application.

Hono er også en af de hurtigste vis man skulle se det fra andre Routers for eksempel Cloudflare Workers
